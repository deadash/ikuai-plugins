      白名单语义: 加入 good.example.com 后, 它及它的所有子域都不再拦截,
      规则库里单独列出的子域条目也一并让开; 同时它的父域条目(example.com)
      也会让开 —— 因为拦截是父域通配的, 不让开的话白名单就无从生效。

      工作原理与接口说明
      

        
1) DNS sinkhole: 插件用设备自带的 DNS 转发器 ikdnsx 跑一个独立实例
        (监听 5353), 静态表里对每个拦截域名写 ipv4 *.域名 0.0.0.0 /
        ipv6 *.域名 :: —— 一条通配即覆盖该域名及其任意层级子域。

        
2) 全网 DNS 纳管: 用 iptables nat 把 LAN 侧所有 UDP/53 查询 REDIRECT 到这个实例
        (与 iKuai 自带 DNS 代理同一套路, 我们的链在最前面), 所以客户端即使自己指定
        8.8.8.8/114.114.114.114 也绕不过去。

        
3) 其余域名照常解析: 该实例同时是转发器, 非拦截域名按设备
        /etc/resolv.conf 里的上游正常解析。

        
4) 安全兜底: 守护进程 + 每分钟的定时守卫负责"进程/规则被冲掉后自动补回";
        一旦实例起不来会主动撤掉劫持规则(fail-open), 不会把 DNS 弄挂。卸载插件后立即恢复原状。

        
局限: 只处理 DNS; 客户端走 DoH/DoT、或广告与业务同域(如某些应用的自家 CDN)
        时拦不住; 也不做 HTTPS 证书级拦截。
